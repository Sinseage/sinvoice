# SINVoice

Голосовой звонок для друзей по прямому IP: один поднимает сервер, остальные подключаются к нему.

Версия 1.2.1 · Автор: Дмитрий Собенин (Sinseage)

## Возможности

- **Поднять сервер** — сервер запускается прямо в программе, вы автоматически входите в звонок.
- **Подключиться** — по адресу `IP` или `IP:порт` (порт по умолчанию 47800).
- **Голос** — по кнопке (глобальная клавиша или кнопка мыши, работает в играх) или по голосу (порог с индикатором уровня).
- **Шумоподавление** — встроенное шумоподавление и эхоподавление Chromium/WebRTC, включается переключателем.
- **Чат** — только на время звонка, нигде не сохраняется. Ссылки кликабельные и открываются в браузере; под сообщением со ссылкой появляется карточка: сайт, заголовок, описание и картинка. Предпросмотр отключается в настройках.
- **Файлы** — передаются вживую через сервер тем, кто сейчас в звонке. Сервер ничего не хранит: файл держится только в памяти получателя, пока идёт звонок, и сохраняется на диск кнопкой «Сохранить». Опоздавшие старые файлы не получают. Лимит — 2 ГБ на файл.
- **Демонстрация экрана** — кнопка с монитором внизу: выбираете экран или окно и качество (720p 30, 1080p 30, 1080p 60). У показывающего в списке участников появляется кнопка «Смотреть»; видео получают только те, кто её нажал. Двойной щелчок по картинке — во весь экран. Звук компьютера не передаётся.
- **Оверлей** — компактный список участников слева сверху поверх всех окон, подсвечивает говорящих.
- **Внешний IP** — после запуска сервера под кнопкой показывается ваш публичный IPv4; нажатие копирует адрес для друзей.
- **Обновления** — при запуске программа проверяет релизы GitHub и предлагает обновиться; в настройках — ручная проверка. Новый exe скачивается рядом со старым, сверяется по размеру и контрольной сумме и после перезапуска заменяет его.
- **Настройки** — ник, аватар, устройства ввода и вывода, громкость микрофона и звука, тёмная или светлая тема, порт и пароль комнаты.

## Сборка через GitHub (с телефона)

1. Создайте репозиторий и загрузите в него содержимое архива так, чтобы `package.json` лежал в корне, а workflow — в `.github/workflows/build.yml`.
2. Откройте **Actions → Сборка SINVoice → Run workflow**.
3. Укажите версию (например, `1.2.1`), при желании — текст «Что нового», и нажмите **Run workflow**.
4. Через 5–8 минут появится релиз `v1.2.1` с файлом `SINVoice-1.2.1.exe`.

Релиз создаётся черновиком, к нему прикладывается exe, и только потом он публикуется — так сборка работает и с включёнными неизменяемыми релизами (immutable releases). Создавать релиз вручную через **Releases** не нужно: на черновики GitHub сборку не запускает, а к опубликованному неизменяемому релизу файл уже не добавить.

Номер версии каждый раз новый: тег неизменяемого релиза нельзя использовать повторно даже после удаления.

Если снять галочку **Опубликовать релиз**, exe только соберётся и будет лежать 1 день во вложениях (Artifacts) запуска.

### Очистка артефактов

Workflow **Очистка артефактов** раз в сутки удаляет все вложения (Artifacts) запусков Actions, чтобы не упираться в лимит хранилища. Запустить вручную: **Actions → Очистка артефактов → Run workflow**. Вложения ручных сборок и так живут 1 день. GitHub пересчитывает занятое место раз в 6–12 часов.

## Сборка на компьютере

Нужен Node.js 20+.

```bash
npm install
npm run dist
```

Готовый файл — `dist/SINVoice-<версия>.exe`. Запуск без сборки: `npm start`.

## Как созвониться

1. Хост нажимает **Поднять сервер**. При первом запуске Windows спросит про брандмауэр — разрешите доступ.
2. Если компьютер хоста за роутером, на роутере нужно пробросить **TCP-порт 47800** (или ваш порт из настроек) на локальный адрес компьютера — он показывается под кнопкой после запуска сервера.
3. Друг вводит ваш внешний IP и жмёт **Подключиться**.
4. Пароль комнаты (необязательно) задаётся в настройках: хост защищает им сервер, участники вводят тот же пароль у себя.

## Что нужно знать

- exe — portable: один файл, без установки. При запуске он распаковывается во временную папку, поэтому первый старт занимает несколько секунд.
- Файл не подписан сертификатом, поэтому Windows SmartScreen может показать предупреждение: **Подробнее → Выполнить в любом случае**.
- Оверлей виден поверх игр в оконном режиме и режиме «Без рамки» (borderless). В эксклюзивном полноэкранном режиме Windows не даёт рисовать поверх игры никаким обычным окнам.
- Демонстрация экрана сжимается видеокартой в H.264 (если не получается — VP8) и идёт через сервер. 1080p 30 — около 4,5 Мбит/с на каждого зрителя, 1080p 60 — около 7; при медленной сети кадры пропускаются, а не копятся.
- Голос идёт несжатым PCM 24 кГц (около 400 кбит/с на говорящего). Для звонка 2–5 человек на домашнем интернете этого хватает; хост раздаёт голос каждого всем остальным, поэтому его исходящий канал нагружается сильнее.
- Настройки и журнал ошибок `sinvoice.log` хранятся в `%APPDATA%\SINVoice`.

## Внешние адреса

Программа обращается в интернет только в трёх случаях:
- `api.github.com` и `github.com` — проверка и загрузка обновлений из https://github.com/Sinseage/sinvoice/releases;
- `api.ipify.org`, `ipv4.icanhazip.com`, `v4.ident.me` — определение внешнего IP после запуска сервера (по очереди, до первого ответа);
- сайт из вашего сообщения — для предпросмотра ссылки. Страницу открывает только программа отправителя и рассылает готовую карточку; получатели на сайт не обращаются. Запросы к локальной сети и служебным адресам заблокированы.

Для обновления папка с exe должна быть доступна на запись. Если exe лежит, например, в `Program Files`, обновитесь вручную со страницы релизов.

## Защита сервера

- Пароль комнаты сравнивается за постоянное время; после 5 неверных попыток адрес блокируется на 5 минут.
- Не больше 4 подключений с одного адреса и 16 участников в комнате; без приветствия соединение закрывается через 10 секунд.
- Ограничена частота чата, смены профиля, голосовых кадров и новых файлов; за систематическое превышение участник отключается.
- Сообщения больше 2 МБ (JSON — больше 300 КБ) отклоняются, голосовые кадры строго фиксированного размера, аватары — только PNG, JPEG и WebP.
- Файл не может прийти больше объявленного размера; отправитель идёт со скоростью самого медленного получателя, поэтому сервер не копит файлы в памяти.
- Получатель держит в памяти не больше 2 ГБ файлов за звонок, лишнее пропускается.

## Устройство проекта

| Файл | Назначение |
|---|---|
| `main.js` | Окна, оверлей, запуск сервера, глобальная клавиша рации |
| `lib/server.js` | Сервер комнаты: ретрансляция голоса, чата и файлов, лимиты |
| `lib/websocket.js` | WebSocket-сервер на встроенных модулях Node.js |
| `lib/logger.js` | Журнал ошибок |
| `preload.js` | Безопасный мост между окнами и главным процессом |
| `src/app.js` | Интерфейс и логика звонка |
| `src/audio.js` | Захват микрофона, буфер джиттера, сведение голосов |
| `src/overlay.*` | Оверлей |
| `.github/workflows/build.yml` | Сборка exe в GitHub Actions |
| `.github/workflows/cleanup.yml` | Ежедневная очистка артефактов Actions |

Подробности устройства — в `DEVELOPMENT.md`.
