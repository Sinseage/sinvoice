# SINVoice — устройство

Версия 1.2.0 · Автор: Дмитрий Собенин (Sinseage)

## Процессы

- **Главный процесс** (`main.js`) — окна, оверлей, сервер комнаты, глобальная клавиша рации (`uiohook-napi`), журнал. Принимает IPC только от своих окон (`trusted()`), значения из IPC проверяет.
- **Главное окно** (`src/index.html`, `src/app.js`, `src/audio.js`) — интерфейс, подключение к комнате по WebSocket, звук. Работает в песочнице (`sandbox`, `contextIsolation`, без Node.js); доступ к главному процессу — только через `preload.js`.
- **Оверлей** (`src/overlay.*`) — прозрачное окно поверх всех, не принимает мышь и фокус.

## Протокол

Один WebSocket на участника, порт по умолчанию 47800.

JSON-сообщения клиента: `hello`, `ping`, `state`, `profile`, `chat`, `file-offer`, `file-end`, `file-cancel`, `screen-start`, `screen-stop`, `screen-watch`, `screen-keyframe`, `chat-preview`.
JSON-сообщения сервера: `welcome`, `join`, `leave`, `state`, `profile`, `pong`, `chat`, `notice`, `error`, `file-offer`, `file-ack`, `file-end`, `file-cancel`, `file-reject`, `screen-start`, `screen-stop`, `screen-keyframe`, `chat-preview`.

Двоичные кадры:

| Направление | Голос | Кусок файла |
|---|---|---|
| клиент → сервер | `[1, 0, PCM×960 байт]` | `[2, 0, fid u32, данные ≤ 64 КБ]` |
| сервер → клиент | `[1, 0, id u16, PCM]` | `[2, 0, id u16, fid u32, данные]` |

Экран: клиент → сервер `[3, флаги, мс u32, кадр]`, сервер → клиент `[3, флаги, id u16, мс u32, кадр]`; бит 0 флагов — ключевой кадр.

Голос — PCM Int16, моно, 24 кГц, кадр 20 мс (480 сэмплов).

### Файлы

Отправитель держит не больше 16 неподтверждённых кусков. Сервер подтверждает куски (`file-ack`), только когда у всех получателей в очереди меньше 2 МБ, — так скорость равна скорости самого медленного получателя, а сервер ничего не копит. Получатели фиксируются в момент `file-offer`: кто зашёл позже, файл не получает. Файл живёт в памяти получателя до конца звонка.

### Ссылки

Ссылки http(s) в чате выводятся элементами `a` и открываются в браузере системы (`setWindowOpenHandler` → `shell.openExternal`). Предпросмотр собирает отправитель: `chat` уходит с клиентским номером `n`, сервер возвращает его вместе с `mid`, после чего отправитель вызывает `lib/preview.js` и шлёт `chat-preview` с `mid`. Сервер принимает предпросмотр только для одного из последних 50 сообщений этого участника и один раз, проверяет поля (`cleanPreview`).

`lib/preview.js`: только http/https, порты 80 и 443, без логина в адресе; каждый IP после DNS проверяется на частные, служебные и зарезервированные диапазоны, соединение идёт на проверенный адрес; не больше 3 перенаправлений (каждое проверяется), 6 секунд, 768 КБ HTML. Картинка (до 3 МБ) раскодируется `nativeImage`, уменьшается до 400 px и пересжимается в JPEG — в карточку попадает только чистый растр.

### Экран

`src/screen.js`. Источник выбирается в своём окне выбора (`desktopCapturer` в главном процессе), захват — `getDisplayMedia` через `setDisplayMediaRequestHandler`, кадры — `MediaStreamTrackProcessor` → `VideoEncoder` (H.264 Annex B, запасной VP8, режим `realtime`). Кадры прореживаются до частоты пресета и не кодируются, пока очередь сокета больше 1,5 МБ. Ключевой кадр — по запросу сервера (новый зритель, потери) и раз в 10 секунд.

Сервер шлёт кадры только подписанным зрителям (`screen-watch`). Если очередь зрителя больше 3 МБ, ему пропускаются кадры до следующего ключевого, а показывающего просят прислать ключевой (не чаще раза в 500 мс). У зрителя `VideoDecoder` рисует в `canvas`; при ошибке или переполнении очереди распаковки он ждёт ключевой кадр.

## Безопасность

- Сервер: лимиты подключений (16 участников, 4 с адреса, 32 без приветствия), блокировка адреса на 5 минут после 5 неверных паролей, сравнение пароля по SHA-256 через `timingSafeEqual`, ограничение частоты по «ведру с жетонами» для каждого типа сообщений, отключение за систематические нарушения, максимум 2 МБ на сообщение (кадр экрана) и 300 КБ на JSON, строгий размер голосового кадра, проверка аватаров регулярным выражением, очистка ников и имён файлов от управляющих символов.
- WebSocket-сервер (`lib/websocket.js`) требует маскированные кадры, проверяет размер по заголовку до приёма данных, рвёт молчащие соединения через 60 секунд.
- Клиент: весь текст выводится через `textContent`, данные от сервера проверяются (`normPeer`, `cleanAvatar`, `cleanFileName`), объём файлов в памяти ограничен 2 ГБ, лента — 500 записей. CSP без `unsafe-inline`.
- Окна: песочница, запрет переходов, новых окон и `webview`; разрешения — только микрофон и выбор устройства вывода для своих окон.
- Ошибки обработчиков сервера и главного процесса перехватываются и пишутся в `%APPDATA%\SINVoice\sinvoice.log` с меткой `[SINVoice]`; программа при этом продолжает работу.

## Производительность

- `TCP_NODELAY` на сокетах сервера — голосовые кадры уходят без задержки Нейгла.
- Кадр для рассылки собирается один раз и пишется всем получателям одним и тем же буфером.
- Голос получателю не отправляется, если у него в очереди больше 512 КБ (сеть не успевает) — задержка не копится.
- Буфер джиттера на участника: старт с 60 мс, при накоплении больше 300 мс сбрасывается до 100 мс.
- Список участников перерисовывается только при изменении состава или состояния; подсветка говорящих — переключением классов раз в 100 мс и только при изменении; оверлей получает данные, только если они изменились.

## Интерфейс

Классы — БЭМ с префиксом `sv-` (`sv-peer`, `sv-peer__name`, `sv-peer_speaking`). Скрипты находят элементы по `data-sv`, а не по классам.

Сетка 8 px. Шкала отступов задана переменными на `.sv-page`:

| Переменная | Значение | Что разделяет |
|---|---|---|
| `--sv-space-heading` | 8 px | заголовок → содержимое, подпись → поле |
| `--sv-space-block` | 16 px | блоки внутри раздела, сообщения в ленте |
| `--sv-space-group` | 24 px | группы в боковой панели, поля окна |
| `--sv-space-sub` | 32 px | подразделы |
| `--sv-space-section` | 40 px | разделы настроек |

Заголовки разделов настроек прижимаются к содержимому поправкой `calc(var(--sv-space-heading) - var(--sv-space-block))`.

## Обновление

`lib/updater.js`: запрос `releases/latest` к API GitHub, выбор файла `SINVoice-<версия>.exe`, сравнение версий. Загрузка разрешена только с `github.com` и доменов файлов GitHub по HTTPS, размер сверяется с данными релиза, SHA-256 — с полем `digest`, если GitHub его отдаёт. Файл скачивается рядом с exe (`PORTABLE_EXECUTABLE_FILE`) как `*.download`; скрытый сценарий PowerShell ждёт выхода программы, заменяет exe и запускает его. Без portable exe (запуск через `npm start`) кнопка открывает страницу релизов.

Внешний IP: `api.ipify.org`, `ipv4.icanhazip.com`, `v4.ident.me` по очереди, ответ проверяется как IPv4, кеш 10 минут.

## Сборка

`npm install`, затем `npm run dist` — portable exe в `dist/`. В GitHub Actions сборка запускается публикацией релиза (`.github/workflows/build.yml`), версия берётся из тега. `cleanup.yml` раз в сутки удаляет артефакты Actions.
