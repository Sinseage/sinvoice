# SINVoice — устройство

Версия 1.1.0 · Автор: Дмитрий Собенин (Sinseage)

## Процессы

- **Главный процесс** (`main.js`) — окна, оверлей, сервер комнаты, глобальная клавиша рации (`uiohook-napi`), журнал. Принимает IPC только от своих окон (`trusted()`), значения из IPC проверяет.
- **Главное окно** (`src/index.html`, `src/app.js`, `src/audio.js`) — интерфейс, подключение к комнате по WebSocket, звук. Работает в песочнице (`sandbox`, `contextIsolation`, без Node.js); доступ к главному процессу — только через `preload.js`.
- **Оверлей** (`src/overlay.*`) — прозрачное окно поверх всех, не принимает мышь и фокус.

## Протокол

Один WebSocket на участника, порт по умолчанию 47800.

JSON-сообщения клиента: `hello`, `ping`, `state`, `profile`, `chat`, `file-offer`, `file-end`, `file-cancel`.
JSON-сообщения сервера: `welcome`, `join`, `leave`, `state`, `profile`, `pong`, `chat`, `notice`, `error`, `file-offer`, `file-ack`, `file-end`, `file-cancel`, `file-reject`.

Двоичные кадры:

| Направление | Голос | Кусок файла |
|---|---|---|
| клиент → сервер | `[1, 0, PCM×960 байт]` | `[2, 0, fid u32, данные ≤ 64 КБ]` |
| сервер → клиент | `[1, 0, id u16, PCM]` | `[2, 0, id u16, fid u32, данные]` |

Голос — PCM Int16, моно, 24 кГц, кадр 20 мс (480 сэмплов).

### Файлы

Отправитель держит не больше 16 неподтверждённых кусков. Сервер подтверждает куски (`file-ack`), только когда у всех получателей в очереди меньше 2 МБ, — так скорость равна скорости самого медленного получателя, а сервер ничего не копит. Получатели фиксируются в момент `file-offer`: кто зашёл позже, файл не получает. Файл живёт в памяти получателя до конца звонка.

## Безопасность

- Сервер: лимиты подключений (16 участников, 4 с адреса, 32 без приветствия), блокировка адреса на 5 минут после 5 неверных паролей, сравнение пароля по SHA-256 через `timingSafeEqual`, ограничение частоты по «ведру с жетонами» для каждого типа сообщений, отключение за систематические нарушения, максимум 512 КБ на сообщение, строгий размер голосового кадра, проверка аватаров регулярным выражением, очистка ников и имён файлов от управляющих символов.
- WebSocket-сервер (`lib/websocket.js`) требует маскированные кадры, проверяет размер по заголовку до приёма данных, рвёт молчащие соединения через 60 секунд.
- Клиент: весь текст выводится через `textContent`, данные от сервера проверяются (`normPeer`, `cleanAvatar`, `cleanFileName`), объём файлов в памяти ограничен 2 ГБ, лента — 500 записей. CSP без `unsafe-inline`.
- Окна: песочница, запрет переходов, новых окон и `webview`; разрешения — только микрофон и выбор устройства вывода для своих окон.
- Ошибки обработчиков сервера и главного процесса перехватываются и пишутся в `%APPDATA%\SINVoice\sinvoice.log` с меткой `[SINVoice]`; программа при этом продолжает работу.

## Производительность

- `TCP_NODELAY` на сокетах сервера — голосовые кадры уходят без задержки Нейгла.
- Кадр для рассылки собирается один раз и пишется всем получателям одним и тем же буфером.
- Голос получателю не отправляется, если у него в очереди больше 512 КБ (сеть не успевает) — задержка не копится.
- Буфер джиттера на участника: старт с 60 мс, при накоплении больше 300 мс сбрасывается до 100 мс.
- Список участников перерисовывается только при изменении состава или состояния; подсветка говорящих — переключением классов раз в 100 мс и только при изменении; оверлей получает данные, только если они изменились.

## Интерфейс

Классы — БЭМ с префиксом `sv-` (`sv-peer`, `sv-peer__name`, `sv-peer_speaking`). Скрипты находят элементы по `data-sv`, а не по классам.

Сетка 8 px. Шкала отступов задана переменными на `.sv-page`:

| Переменная | Значение | Что разделяет |
|---|---|---|
| `--sv-space-heading` | 8 px | заголовок → содержимое, подпись → поле |
| `--sv-space-block` | 16 px | блоки внутри раздела, сообщения в ленте |
| `--sv-space-group` | 24 px | группы в боковой панели, поля окна |
| `--sv-space-sub` | 32 px | подразделы |
| `--sv-space-section` | 40 px | разделы настроек |

Заголовки разделов настроек прижимаются к содержимому поправкой `calc(var(--sv-space-heading) - var(--sv-space-block))`.

## Сборка

`npm install`, затем `npm run dist` — portable exe в `dist/`. В GitHub Actions сборка запускается публикацией релиза (`.github/workflows/build.yml`), версия берётся из тега. `cleanup.yml` раз в сутки удаляет артефакты Actions.
